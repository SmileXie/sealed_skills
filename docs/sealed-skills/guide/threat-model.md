# 威胁模型与保证边界（诚实版）

这份文档写给**技能作者、市场运营者、以及准备采纳 Sealed Skills 的团队**。它的目的是把
「我们保证什么、不保证什么、哪些还没验证」一次讲清楚，让你能**准确地**向用户宣传、也能
判断它是否适合你的业务。

一句话：Sealed Skills 是**商业护栏**，不是军用级防拷贝。它挡的是「顺手复制 / 转发 / 白嫖」，
不是有决心、有工具的逆向工程师。

## 1. 威胁等级：B

我们只针对 **B 级**对手：

- 技术上有能力（会看文件、改配置、装插件），但**不会**为破解一个技能投入专业逆向工程；
- 动机是「省钱 / 图方便」，遇到足够高的门槛就会放弃或付费；
- 不是有组织的盗版团伙，也不是愿意花几天反编译的研究者。

**对 A 级（专业逆向）对手，我们不设防，也不做任何承诺。** 本生态里没有任何一项技术能挡住
能在你机器上跑调试器、注入进程、改内核的人——因为技能明文最终必须在用户的进程内存里出现，
才能被送进模型。

## 2. 信任边界

| | 内容 |
|---|---|
| **可信** | 作者 Ed25519 签名私钥、pack master key、授权服务器及其签名私钥、服务器数据库 |
| **不可信** | 用户机器上的一切——文件系统、进程内存、loader 插件代码、会话日志、临时目录、遥测、系统时钟 |

**结论**：所有授权判定都必须建立在**密码学验证**之上，绝不依赖客户端「守规矩」。
即使攻击者把开源的 loader 改到面目全非，他也**无法伪造作者签名**、**无法在没有服务器签名私钥的
情况下签出有效 license**、**无法在没有设备私钥的情况下解出条目密钥**。

## 3. 成立的安全属性（S1–S7）

| 编号 | 属性 | 实现机制 | 验证 |
|---|---|---|---|
| **S1** | 磁盘上不出现技能正文/脚本源码明文（含会话日志、spill、临时文件、错误输出、遥测） | 虚拟技能无磁盘路径；日志掩码写占位符；脚本源码只经 stdin；用后零化 | 金丝雀泄漏扫描 `pnpm leak-gate` + `disk-leak-check` |
| **S2** | 无有效 license 无法解密任何条目 | 逐条目 CK 封装；缺授权 → `NOT_GRANTED` | 授权测试 |
| **S3** | license 与设备绑定，换机不可用 | CK 用设备 X25519 公钥 ECDH 封装；换机 GCM tag 校验失败 | 对抗测试 |
| **S4** | 试用 license 解不开非试用条目 | license 只含被授权条目的 `keys` | 授权测试 |
| **S5** | 篡改包内容必被检测 | manifest Ed25519 签名 + 逐条目 AES-GCM 认证 | 篡改测试 |
| **S6** | 包密文与客户无关，license 是唯一按客户产物 | 同一份 `.sealedpack` 分发给所有客户 | 构建期检查 |
| **S7** | 吊销在 TTL 内生效 | 客户端续期被拒 → 删除缓存；最坏延迟 ≤ 一个 license TTL（7 天） | 服务端 + 客户端测试 |

这些属性在 M1–M3 的测试与冒烟中都有自动化断言；**未验证**的部分见 §5、§6，不会被写成「已通过」。

## 4. 明确**不**保证的（「不要指望」清单）

- **不防专业逆向**：有本机调试权限的用户，最终可以把明文从进程内存里捞出来。
- **不防模型提供方**：送进模型的内容，模型提供方一定看得到。这不在本生态能解决的范围。
- **不做实时踢下线**：客户端只在进入续期窗口（到期前 2 天）才联系服务器，因此吊销最坏要等
  一个 TTL（7 天）后的下次续期才生效。
- **不保证「密文无法被复制」**：`.sealedpack` 可以随便拷，但拷到别的设备上也解不开。
- **不防「用户自愿把明文读出来分享」**：如果用户能正常使用技能，他就能把看到的内容手动转述出去。
  这是任何「可用即可见」系统的固有上限。
- **不承诺跨版本兼容**：v1 线格式冻结；未来大版本升级需要升级 loader。

## 5. M3 实测残余（在真实 dsh `0.2.0-rc.2` 上）

M3 把「明文只在内存」升级为可验证的运行时保证，但也暴露了几处**如实的缺口**。它们都记在
`docs/sealed-skills/notes/dsh-0.2-seams.md`，此处汇总对使用者的影响：

- **缺插件的 harness 会拒绝整条会话（上游缺口）**：dsh 0.2.x 的 `session.append` 无法携带
  `ignorable: true`，插件只能在 apply 时把 `sealed/redacted` 注册进运行时的
  `KNOWN_SESSION_EVENT_TYPES`。**代价**：用过 sealed 技能的会话，若在**未安装本插件**的 harness 上
  打开，读取器会**整条拒绝该会话日志**，而不是优雅回退成占位符。这是 dsh 上游缺口
  （建议 upstream 提供 append-with-ignorable 或 session 级 redaction API）。
- **`invariants` 哨兵是「检测」而非「阻断」**：已提交会话事件若含 sealed 明文，哨兵会告警，
  但**不会**关停 provider；且真实路径的唯一信号是 `ctx.logger.warn`
  （dsh 会把 `session/event` 监听器的异常吞进 `logger.warn`）。它是纵深防御，不是最后一道闸。
- **检测靠子串匹配**：leak-gate / 哨兵用明文子串扫描。**base64 / hex 编码、或跨字段拆分**的正文
  **检不出来**。这是已知盲区，属于「检测能力」而非「加密能力」的限制。
- **脚本执行依赖沙箱后端**：沙箱不可用或非 fully-enforcing 时，脚本工具**拒绝注册**
  （`sandbox-not-enforcing`，fail-closed），但**纯提示词技能不受影响**。子进程输出若回显源码 →
  标记 `output-redacted`。

## 6. 尚未验证（UNVERIFIED，不得当作已通过）

以下项目在仓库中**没有**端到端证据，请勿在宣传材料里写成「已验证」：

1. **完整 dsh shipped profile 的真实模型回合**（`dsh-base` + `dsh-headless`）需要
   `DEEPSEEK_API_KEY`，本仓库**未**跑通。
2. **Windows 真实沙箱后端**（`dsh-sandbox-local` / `dsh-pwsh-sandbox`）可用性**未启动**；
   只测了注入「不可用 / 非 enforcing」的分支。
3. 真实 `ToolRuntime.register` 进入 booted `ctx.tools`——用假 runtime + 真实 `defineTool` 证明，
   端到端注册未驱动。
4. 真实 `ctx.effect` 对 `sealed.scripts` 的 teardown——用假 ctx 测试（省略 `effect`）。
5. Python 执行分支——只验证了 argv 形状；**v1 实际只支持 Node ESM**。
6. `invariants` 哨兵的插件接线（arming）——结构性验证 + 服务可见性探针，无 in-repo 端到端断言。
7. 真实 harness 的 `spill/`、`logs/`、`telemetry/` 表面未验证；leak-gate 这几项是 **gate 自造内容**，
   仅 durable session log 在 `SEALED_DSH_LAB=1` 下为真。
8. gated 真机子检查在 CI 中不运行（CI 未设 `SEALED_DSH_LAB`），CI 只证明 standalone gate。

## 7. 平台与部署相关

- **设备私钥现状**：M2 里设备 X25519 私钥以文件形式落盘（`$SEALED_HOME/device.json`）。
  OS 密钥库后端（Windows DPAPI / macOS Keychain / Linux libsecret）属于 **Plan 2B，尚未实现**。
  在实现之前，「设备私钥被本地读取」属于残余风险——但即使读走私钥，也只能解开**该设备已被授权**的
  条目，无法扩大授权范围，也无法伪造服务器签名。
- **授权服务器被攻破**：会导致该 pack 的 master key 泄漏（可解出全部条目）。缓解：master key
  用 `SEALED_SERVER_MASTER_KEY` 加密静态存储、管理通道走 TLS、启用审计与限流。服务器在**你的**
  信任边界内，别把 master 或作者私钥交付给终端用户。
- **时钟**：客户端做时钟回拨检测（相对「上次见到的最大时间」），但系统时钟终究不可信；
  过期判定以 `exp` / `grace_until` 为准。

## 8. 宣传用语建议

| 建议这样说 | 避免这样说 |
|---|---|
| 「源码不出密文包，磁盘上拿不到明文」 | 「无法破解」 |
| 「按设备授权，换机不可用」 | 「DRM 级防拷贝」 |
| 「可试用、可续费、可吊销（TTL 内生效）」 | 「实时踢下线」 |
| 「面向不会为破解付费的用户（威胁模型 B）」 | 「军事级加密」 |

## 9. M5 与 Plan 2B 的定位

- **Plan 2B**：OS 密钥库后端，把设备私钥从明文文件升级为系统级保护。它降低「本地读取私钥」的
  风险与便利性，但**不改变**威胁模型等级。
- **M5**：`DecryptBackend` 原生 / WASM 化与更深的内存防护。它提高逆向成本，但**依然不能**阻止
  有足够权限的用户。任何声称「M5 之后就无法提取」的说法都是不诚实的。
